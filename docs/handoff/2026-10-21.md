## 1. 现在在哪

- 已发布 tag：`v0.3.0`、`v0.4.0`、`v0.5.0`、`v0.5.1`、`v0.6.0`。都没有 GitHub Release，**不发 npm**（包名 `dsh-token-budget` 在 npm 上已被占）。
- 0.6.0 范围：E5a（交接精简）+ E5b（换窗记录进会话日志，`src/window/switch-log.ts`，投影 v4）+ 普通模式 + 普通会话与 agent-teams 互接。六步全部完成，见 `docs/design/0.6.0.md` §4。
  - 身份三态：普通会话（不在团队的顶层会话）/ 队长 / 成员；子会话不生效（E1，工具隐藏）。
  - 普通会话有提醒、换窗、【交接】、`context_*`、`history_*`；节奏由下拉设置 `plainPace` 选 `member`（默认，先兜底再换窗）或 `captain`（只提醒）。
  - 会话笔记 `notes/sessions/<会话>.md`：普通会话的工作记忆；开队后即队长笔记，成员读 `captain.md` 映射到它；散队后原地保留。普通会话可读写 `workspace.md`、可读 `records/workspace-snapshots/`，看不到队员笔记、待合并清单、全文记录。
- 验证：`pnpm test` 116/116，`pnpm typecheck`、`pnpm build` 通过；真机（DSH 0.2.1-rc.2 headless + agent-teams 0.1.25）跑通：普通会话写笔记 → 同会话开队 → 成员读 `captain.md` 得到原文 → 散队后笔记仍在。

## 2. 用户的长期规则（必须遵守）

- 不写任何旧版本数据/路径的升级、兼容、迁移代码；代码尽量少、不冗余。
- 不做 fork 相关设计或代码（快照/时间旅行另有项目 newsnap）；已有的 `inheritedEventCount` 过滤保留。
- 先讨论设计，用户同意后再写代码。设计没写到的地方自己定、实现、再告诉用户。每步完成后用**白话**汇报（用户觉得术语难懂）。
- 不擅自加设置项/变量；升版本、打 tag 要用户点头。
- 真模型运行尽量少（DeepSeek 余额有限）。
- 提交：中文小提交，直接推 `main`，不 force-push；不碰分支 `poc/0.3.0`；只提交 `src/ test/ docs/ README.md package.json`，不提交 `lib/`、`pnpm-workspace.yaml`。推之前先 `git fetch && git rebase origin/main`（用户自己也会往 main 推文档）。

## 3. 怎么验证

- 单测：`pnpm test`（node --test + strip-types；不要用 TS 构造函数参数属性）。
- 真机最省钱的方式是 headless：建一个 profile，bundles 为 `@deepseek-ai/dsh-base`、`@deepseek-ai/dsh-headless`、`@nanmicoder/dsh-agent-teams`、`dsh-token-budget`，把 `lib/` 拷进 profile 的 `node_modules/dsh-token-budget`，然后
  `dsh --profile <名> --json [--session-id <id>] "任务"`，在一个空工作区里跑，查 `.agent-teams/.context/` 与会话日志（`*.jsonl.zstd`）。
