## E4 w1 交接只发一次

**问题**：预算提醒与 w1 交接原本都是 `systemPrompt.context`。宿主把所有 context 拼成一段快照，任一项变化就整段重发（`dsh-agent-loop` `RuntimeContextProjection.project`），预算每升一档交接就跟着重发。

**做法**
- 删除 runtime context `dsh-token-budget:handoff` 及 assemble 中重算它的分支；预算提醒不变。
- 新增 `agent/pre-step` 监听：先 `next()`，reject 原样返回；窗口为 w1、日志中尚无交接、有团队身份时，在本步消息尾部追加一条 `createUserMessage`，`source = { kind: 'dsh-token-budget/handoff', form: 'instructions' }`，正文为 `initialHandoffText`，外包 `<system-reminder>`。
- “是否已发”记在窗口投影（`tokenBudgetWindow`，stateVersion 3，新字段 `handoffSent`）：随日志重放，冷启动与 fork 自动恢复；继承前缀里的交接也算，fork 出来的会话不重发。投影不可用时不发。
- 压缩后不补发：任何摘要都进入 w2，由摘要位置的完整【交接】接替。

**取舍**：发出后在 w1 内切换 notes/teamHistory 开关，交接不再更新（只追加、不改写）；工具开关仍即时生效。

**测试**：`applyWindowEvent` 记录交接、`needsInitialHandoff(windowIndex, handoffSent)`。

## E1 普通子会话隐藏本插件工具

- 隐藏条件：子会话 S 不是成员，且父会话 P 不是任何团队的队长（沿用 agent-teams `teamLeadMatch`：等于 captainSessionId，或顶层会话、祖先链含队长且不含成员）。
- 时机：`agent/created`。同一会话的 Agent 会重建（成员每轮、压缩后），按会话 id 记住第一次的决定（进程内），保持前缀稳定。
- 做法：`agent.ctx.tools.restrict({ deny })`，只 deny 8 个工具中当时已注册的；随子会话销毁自动撤销。
- 祖先链或状态读不到时 fail-open，保留工具。祖先链先查活会话，再查 `sessionPersistence.stat`，深度上限 32。
- 文件 `src/team/lineage.ts`；纯函数 `shouldHideTools`、`teamLeadMatch`、`resolveLeadIdentity` 测试。不加设置，不给队长 fork 额外权限。
- 已知边界：创建后才打开的工具开关（如 notes）不在 deny 里，隐藏的子会话会看到新注册的工具。
