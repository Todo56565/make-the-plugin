> 状态：**设计已定稿**，未开始实现（2026-10-17）。

## 2. 文件布局

> 2026-10-17 定稿。依据 agent-teams 0.1.23 源码（`state.ts`、`tools.ts`）与 `future-ideas.md` 的扩展需求。

### 2.1 agent-teams 的事实（布局的前提）

- 状态根 `stateRoot = <队长会话 cwd>/<stateDir>`（默认 `.agent-teams`），同工作区所有主 Agent 共用；分类只靠 teamId，不分主 Agent。
- `teamId = sanitizeKey(队名)`：小写字母/数字/`-`，最长 48 字符 + 摘要，永不以 `.` 开头，故 `.context` 不会与团队目录撞名；agent-teams 扫描时无 `team.json` 的目录跳过。
- 同名检查只看活动团队：归档后可重建同名团队；同一 id 再次归档会**删除上一代归档**（`archiveTeamDir`）。本插件的记录可能是旧代唯一留存，故需「代」：用 `team.json` 的 `createdAt`。
- 归档 = 整个 `<teamId>/` rename 到 `archive/<teamId>/`（删除团队、丢弃待审方案都走这里），无可靠事件，只能扫描发现。
- 任务 id 为团队内 `t<taskSeq>`；`attempt` 是递增整数；`attemptId` 为 UUID，但**取消、改派时被清空**，且同一 `attempt` 下可换新 `attemptId`。故键与目录用 `attempt` 整数，`attemptId` 只作元数据。
- agent-teams 没有提示主 Agent 注意队名的提示词（`name` 参数只写「作为稳定 id」）。
- 质量闸门默认只排除 `.agent-teams/`，故根目录暂留其下。

### 2.2 布局

```
<stateRoot>/.context/
  layout.json                       布局版本 + 迁移记录
  notes/                            ① 模型经 team_notes 写
    workspace.md
    teams/nanmi/<teamId>@<代>/<fileKey>.md
  shared/                           ② 跨插件协议区，文件带 schema 版本
    pending.jsonl                   待合并清单（模型看到虚拟 workspace.pending.md）
    locks/workspace.md.lock         跨插件写锁
  records/                          ③ 仅插件写，只追加，永久
    full/0001.md …
    workspace-snapshots/000001.md …
    teams/nanmi/<teamId>@<代>/<taskId>/a<attempt>/<seq>-<hash8>.md
    teams/nanmi/<teamId>@<代>/notes/        该代结束后搬入的在用笔记
  state/                            ④ 运行状态，可删、自动重建
    sessions/<sessionId>.json
    full-cursor.json                全文游标（可由全文重建的缓存）
  ext/<插件名>/                      ⑤ 其他插件自留地，本插件不读不写
```

- `<代>` = `createdAt` 的 base36（约 8 位），缩短路径。
- `nanmi` 是团队后端层；将来官方团队为 `teams/official/<队长 session id>/`（官方 id 不重名，不带代后缀）。
- 快照文件名不含 fileKey，归属记在全文条目与快照元数据里。

### 2.3 三层规则

1. 第一层按「谁能写、丢了能否重建」分为 ①～⑤；权限校验与清理策略按区写一次。
2. 第二层按作用域：工作区级直接放区内；团队级 `teams/<后端>/<id>[@<代>]/`；会话级 `sessions/<sessionId>`；将来新作用域（如共议会的实例级）加 `instances/<主会话 id>/`，不动已有。
3. 第三层按功能。

新功能只问三件事：谁写？丢了能否重建？作用域？答案决定唯一位置。

### 2.4 演进与健壮性

- **虚拟路径与物理路径分离**：模型只见 `workspace.md`、`workspace.pending.md`、`teams/<teamId>/<成员>.md`、`records/…` 等虚拟路径，插件映射到当前代；物理布局变化不改提示词与工具。
- **layout.json**：启动发现版本旧即迁移，先写新位置再删旧位置，可重复执行。0.3.0 → 0.4.0 为第一次迁移（`notes/teams/<teamId>/` → `notes/teams/nanmi/<teamId>@<代>/`）。没有对应活动团队的旧目录直接删除（用户 2026-10-17 决定：0.3.0 期间的团队都是测试数据）；新目录已有同名文件时保留新的。
- **命名**：id 先规范化；会重名的实体加代后缀；编号补零、永不复用。
- **Windows 路径长度**：单测覆盖最长路径（48 字符 teamId + 代 + taskId + attempt + 文件名）。
- **结束代的发现**：不另存「已见团队」文件；扫描 `notes/teams/nanmi/*@*`，对不上活动 `team.json`（不存在或 `createdAt` 不同）的代即已结束，然后：删除无全文条目的 attempt 目录、把在用笔记搬入 `records/…/notes/`。不依赖 `archive/` 对得上（可能已被覆盖）。插件启动时补扫一次。
- **协议文件**：清单物理上是 `shared/pending.jsonl`（带 schema 版本），由插件渲染成虚拟 `workspace.pending.md`；全文条目与游标也带版本号。
- **锁与原子写**：锁文件写 pid 与时间，超时可接管；rename 加 Windows EPERM 重试（同 agent-teams `renameWithRetry`）。
- **records 总量**：设置页显示占用；提供「清理已结束超过 N 天的代」，默认关。
- **已核实（2026-10-17，agent-teams 0.1.23 / harness 源码）**：
  - 工作区根：子会话 `header.cwd` 由宿主直接复制父会话的 `header.cwd`（`subagent/child-agent.ts` `childSessionMeta`），agent-teams 队长与成员都用 `session.header.cwd ?? process.cwd()` 拼状态根。插件必须用同一表达式，**不能**用 `workingDirectory` 服务（成员实际工作目录可能被改到别处）。
  - 成员重名：`agent_teams_add_member` 拒绝本团队代内任何用过的名字（含已移除，按 `sanitizeKey` 比较），故同一代内 fileKey 不会被新成员继承。唯一例外是方案待审期移除的成员，批准时被丢弃、名字可复用，但它从未启动、没有笔记。跨代重名由 `@<代>` 隔离。
  - `e<seq>` 稳定：会话日志只追加且 `seq = 下标` 连续；fork 时子会话原样复制 `0..boundary` 的事件（同 seq），之后是 `session/end-seed` 标记与子会话自己的事件。继承段在父子两边 seq 相同、内容相同，限定形式 `<sessionId>/w<n>/e<seq>` 唯一可定位；成员窗口号只计 fork 之后的压缩（`src/history/model.ts` 已如此）。

### 2.5 历史坐标（对应 Codex window id + item id）

| Codex | 本插件 | 作用域 | 用法 |
|---|---|---|---|
| window id | `w<n>`（压缩计数） | 单会话 | 不变 |
| item id | `e<seq>`（事件序号，压缩后不变） | 单会话 | 笔记提示改为记录 `w<n>/e<seq>`（替代「窗口 + 关键词」） |
| — | 信件 `message_id` | 团队 | 不变 |
| — | `<teamId>@<代>:<taskId>:<attempt>` | 团队代 | 全文主键 |
| 跨线程引用 | `<sessionId>/w<n>/e<seq>` | 工作区 | 全文条目与快照元数据记录此限定形式，供队长/合并助手定位任意成员原文 |

## 3. 全文记录

- 条目来源：`team.json` 中进入终态的任务。完成信不可靠（可能被 `isCurrentMail` 作废），以 `team.json` 为准。
- 字段：团队、任务、成员、`attempt` / `attemptId`、状态、`output`、`verdict` / `findings`、`changedPaths`、`commandsRun`、`acceptanceResults`，以及成员笔记快照路径。
- 下游派单只带每项约 2,000 字符的 output，全文保存完整 output 有增量价值。
- 唯一键 `<teamId>@<代>:<taskId>:<attempt>`（`attemptId` 取消/改派时被清空，只作元数据）；去重以全文条目自带的唯一键为准；`state/full-cursor.json` 只是记录「已写入哪些键」的加速缓存，替代只在内存的 `CompletionTracker`，插件重启或未运行期间完成的任务也能补记。先追加后更新游标，尾部按唯一键去重。
- 游标丢失或损坏：扫描全部全文分卷重建，不当作首次运行。
- 基线：工作区首次运行 0.4.0（既无全文分卷也无游标，典型为从 0.3.0 升级）时，把 `team.json` 里已是终态的任务直接记入游标，不写全文条目、不进待合并清单（旧任务没有成员笔记快照，且避免清单被一次塞满）。全文记录没有开关，始终开启。
- 分卷 `records/full/0001.md` 起，单卷 1 MB，单条 32 KB（超出截断 output 并标注原长度）。
- 条目附成员会话的限定历史坐标 `<sessionId>/w<n>/e<seq>`（§2.5）。

## 4. 合并材料与快照取样

### 4.1 材料

| 材料 | 默认 | 合并模型 | 队长 |
|---|---|---|---|
| 当前 `workspace.md` + 待合并成员笔记 | 是 | 插件喂入 | 自读 |
| a 近期任务记录（上次合并以来的全文条目，上限 16,000 字节，超出保留最新） | 可选 | 插件喂入 | 提示建议 |
| b `workspace.md` 历史快照 | 可选，实验性 | 插件按 §4.2 取样喂入 | 只给路径一句话 |

### 4.2 b 的取样：余弦分布

- 快照按时间从旧到新编号 `1..N`（1 = 最旧，N = 最新）。
- 取 `m` 份，采用切比雪夫-洛巴托点：`x_k = (1 − cos(π·k/(m−1))) / 2`，`k = 0..m−1`；序号 `i_k = 1 + round(x_k·(N−1))`；去重、排序。
- 效果：两端（最旧、最新附近）间隔小，中间间隔大；最旧和最新必定入选。
- 喂给合并模型的顺序：从旧到新。
- 示例：`N=10, m=5 → 1,2,5,9,10`；`N=20, m=6 → 1,3,8,13,18,20`；`N=50, m=8 → 1,3,10,20,31,41,48,50`。
- `m`：用户配置（`mergeSnapshotCount`，默认 5），设置页按 `m × workspaceMaxBytes` 显示最大可能体积。
- 最新一份快照不喂：当前 `workspace.md` 已在默认材料里，余弦取样在 `1..N−1` 上进行。
- 快照整份喂入，不截断。
- 唯一保险：材料总量超出合并模型上下文窗口时，从中间开始整份丢弃，最旧一份保留；最旧一份单独也放不下时截取开头并标注。「自定义」同样适用，并在设置页提示。
- 另有「自定义」模式：按用户在看板上勾选的编号喂入，同样从旧到新。编号必须稳定、永不复用；被勾选的编号精简时一律保留，不计入 m（额外保留）。
- `N < m` 时全部喂入。

### 4.3 低耦合要求

取样逻辑放在独立纯函数模块（如 `src/notes/snapshot-sampling.ts`），输入 `N` 与预算、输出序号列表，不读文件、不依赖合并流程。合并代码只依赖这个接口，便于后续替换或整块删除。

## 5. 工具与提示词变化

- `team_notes`：成员对 `workspace.md` 的 `write` / `append` 一律拒绝；工具描述同步改写（现为「可写自己的笔记和 workspace.md」）。
- `read` 加 `start_line` / `stop_line`；无范围读大文件时只返回末尾一段，并附总行数与分段读提示。
- `read` 接受 `records/…` 虚拟路径（只读，不加新工具）；成员只能读本团队的快照。
- 读 `workspace.md` 时附带清单内容。
- 清单条目带短 id；队长用 `team_notes` 新增的 `resolve` action 按 id 删除；合并模型合并成功后由插件删除已喂入的条目，模型无需约定输出格式。
- 笔记提示词：「仍在处理的请求」改为记录 `w<n>/e<seq>`（§2.5）。
- 关闭合并时如何知道队长处理了哪份笔记：以清单删行为准。

## 6. 配置

| 参数 | 默认 | 说明 |
|---|---|---|
| `maxFileBytes` | 10,000 字节 | 沿用现 `maxFileBytes`，不再管 `workspace.md` |
| `workspaceMaxBytes` | 20,000 字节 | `workspace.md` 上限 |
| `fullVolumeMaxBytes` | 1 MB | 全文单卷 |
| `fullEntryMaxBytes` | 32 KB | 全文单条，超出截断并标注 |
| `workspaceSnapshotKeep` | 自动（全留） | 自动时显示快照相对路径；非自动设 m，累计到 100 份时按余弦精简到 m 份 |
| `mergeRecentTasks` | 关 | 合并材料 a |

| `mergeSnapshotPicks` | 空 | 「自定义」时看板勾选的编号 |

b 不设字节上限，只在超出合并模型上下文窗口时按 §4.2 丢弃。

## 8. 实现拆分（2026-10-17 定）

每步一两个小提交、各带单测；真跑只在第 12 步做一次。

1. 布局地基：`src/context/layout.ts`（各区路径、代 base36、`layout.json`）；跨插件文件锁 + 原子写 EPERM 重试；状态根统一 `header.cwd ?? process.cwd()`；最长路径单测。
2. 迁移 + 虚拟路径映射：0.3.0 的 `notes/teams/<id>/` → `notes/teams/nanmi/<id>@<代>/`，可重复执行；`paths.ts` 改为虚拟→物理解析，模型看到的路径不变。
3. 权限与上限：成员禁写 `workspace.md`（工具层拦截 + 描述改写）；新增 `workspaceMaxBytes`。
4. 读取：`read` 加 `start_line` / `stop_line`，无范围读大文件返回末尾 + 总行数；`records/…` 只读路径。
5. 成员笔记快照：换窗与终态时拍，hash 去重，`a<attempt>/<seq>-<hash8>.md`，元数据含 `<sessionId>/w<n>/e<seq>`。终态快照的坐标从成员持久化会话日志算出：取任务 `updatedAt` 之前的最后一个条目（成员之后接的新活不算）；读不到日志或缺 `updatedAt` 外的异常时退回只记会话 id。不靠识别 `agent_teams_update_task` 调用定位，避免绑定上游工具名与参数。
