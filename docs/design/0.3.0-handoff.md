## 1. 已定决策

| # | 决策 | 说明 |
|---|---|---|
| 1 | 默认不用 LLM 摘要 | 对齐 Codex token-budget：换窗不调用模型，摘要位置换成零模型调用的「换窗信息」。实现上直接接管 `summarize()` 返回模板，**不发出任何摘要请求**（不是先请求再丢弃）。LLM 摘要以后作为可选项加回，届时再做模型选择。 |
| 2 | 不做模式开关 | 原先的 hybrid/template/llm 三选一取消。 |
| 3 | 强制兜底，对齐 Codex | 到压缩点时如果本窗口没写过自己的笔记，不马上换窗，先给一段超时额度，注入兜底提示：本窗口只允许写一次笔记，然后换窗。 |
| 4 | 主动换窗工具 | 新增类似 Codex `new_context` 的工具，模型记完笔记后自己换窗。第一次提醒时就说明，后续提醒不再重复。 |
| 5 | hint 与模板合并 | 对齐 Codex：常驻说明 + 每窗口一段换窗信息。换窗后不再单独注入 hint。 |
| 6 | 换窗信息只给指针 | 不放笔记全文。顺序：任务、自己的笔记、共享笔记、团队信件，最后是上一窗口 id 和 history 指针。 |
| 7 | 笔记新鲜度 | 自己的笔记文件 mtime ≥ 本窗口开始时间，即视为本窗口写过。workspace.md 不算，不加 token 增量阈值。 |

## 2. 预算提醒（可配置）

配置项沿用 0.2.0：`remindAtRatio`（第一次提醒，默认 0.37）、`compactAtRatio`（上限，默认 0.45）、`bucketStep`（步长，默认 0.03）。

提醒档位 = `remindAt + k × step`，取严格小于 `compactAt` 的值。

新规则：**`(compactAt − remindAt) / step` 不是整数时，去掉最后一次提醒**，因为它离上限不足一个步长。

| 配置 | 档位 | 说明 |
|---|---|---|
| 0.37 / 0.45 / 0.03（默认） | 37、40（43 去掉） | 8/3 不是整数 |
| 0.37 / 0.45 / 0.04 | 37、41 | 8/4 = 2 |
| 0.36 / 0.45 / 0.03 | 36、39、42 | 9/3 = 3 |

按新规则，默认配置只剩两次提醒。是否把默认步长改成 0.04（37/41）待定。

提醒文本：

- 第一次：用了多少、多少时换窗、现在记笔记，**并说明记完可调用换窗工具自己收尾**。
- 之后各档：只说用量和「尽快记笔记、换窗」，不再重复换窗工具的说明。

## 3. 压缩点流程

```
已用 ≥ compactAt
  ├─ 本窗口写过自己的笔记 → 换窗，摘要位置写入换窗信息
  └─ 没写过 → 注入兜底提示，给额外额度 fallbackBufferTokens（默认对齐 Codex 16384）
        ├─ 写了笔记（或调用了换窗工具）→ 换窗
        └─ 用完额度仍没写 → 照样换窗，换窗信息里注明「上一窗口未写笔记，请先用 history_* 恢复」
```

兜底提示（对齐 Codex `auto_compact_fallback_prompt`）：本窗口上下文已用尽，不要继续任务、不要给最终答复；新窗口不会自动带上本窗口内容；现在只调用一次 team_notes 写下检查点（目标、决定、进展、经验、下一步，以及仍在处理的请求在哪个窗口、用什么关键词能搜到），然后调用换窗工具。

待 PoC：

- 插件能否把压缩推迟一轮（45% 是我们自己在 `system-prompt/assemble` 里触发的）；
- 兜底期间能否只暴露 team_notes 和换窗工具（与 restrict 议题相关）；
- 换窗工具能否在工具调用内触发压缩。

## 4. 常驻说明（system section，每个 agent 冻结一次）

在 0.2.0 笔记说明的基础上：

- 「压缩后早先的原始消息只剩摘要」改为「换窗后早先的原始消息不在上下文中」；
- 增加：记下仍在处理的请求所在的窗口 id 和可搜索的关键词（我们的实时上下文里没有 `[id: ...]`，条目 id 只能在 history 工具的输出里看到）；
- 增加：换窗信息里出现「上一窗口」说明刚换过窗，先读自己的笔记，再按需用 history_* 回看；
- 增加：笔记和历史是内部工作记录，不要在对外回复里提起。

## 5. 换窗信息

数据来源：

- 窗口 id 用 history 模型的编号（`w1` 起，每个 `compaction/summary` 加一），与 `history_*` 一致，不用 window counter；
- 任务来自 team.json 缓存；
- 笔记元数据来自文件 stat。

首个窗口（还没换过窗）注入精简版：身份、任务和工具指针，没有「上一窗口」一行。换过窗以后注入完整版，取代摘要，不再另注入 hint。

完整版顺序见 §6 样例。超过 `hintMaxBytes` 时，先删除「最近改动的笔记」列表，再删除其余可选行，最后才整条不注入。

## 6. 换窗信息样例（成员 bob）

```
【交接】
团队「接口重构」（team-7f3a），你的身份：bob（成员）。
任务：t2 接口联调（in_progress），当前 attempt 59752a8f
你的笔记：teams/team-7f3a/bob.md（42 行，本窗口 14:20 更新）— 先读它
共享笔记：workspace.md（18 行，队长维护）
最近改动的笔记：teams/team-7f3a/alice.md（30 行，14:05）
队长和队友的信：team_history（含已读）
上一窗口 w2 已结束，原文不在当前上下文中，可用 history_list_items / history_search_contents / history_read_item 按窗口 id 回看。
以上是换窗时的快照，任务和笔记以 agent_teams 工具和 team_notes 为准。
```

未写笔记时，第 3 行改为：

```
你的笔记：teams/team-7f3a/bob.md（42 行，上一窗口未更新）— 上一窗口没写笔记，先用 history_* 恢复进展
```

队长版：任务行改为「团队未完成任务：3 个（t2、t4、t5），详情以团队任务为准」，共享笔记行改为「由你维护」。
