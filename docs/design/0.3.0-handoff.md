# 0.3.0 设计：换窗交接（讨论稿，未实现）

> 状态：设计讨论中，2026-10-16。未确认前不写代码、不升版本。
> 参考：Codex token-budget 模式（`codex-rs/core/src/compact_token_budget.rs`、`core/src/session/token_budget.rs`、`core/src/context/token_budget_context.rs`、`models-manager/models.json` 的 `token_budget` 默认值、`core/src/tools/handlers/new_context_window_spec.rs`）。注意：不是 Codex 普通压缩（`compact.rs`）。

## 1. 已定决策

| # | 决策 | 说明 |
|---|---|---|
| 1 | 默认不用 LLM 摘要 | 对齐 Codex token-budget：换窗不调用模型，摘要位置换成零模型调用的「换窗信息」。实现上直接接管 `summarize()` 返回模板，**不发出任何摘要请求**（不是先请求再丢弃）。LLM 摘要以后作为可选项加回，届时再做模型选择。 |
| 2 | 不做模式开关 | 原先的 hybrid/template/llm 三选一取消。 |
| 3 | 强制兜底，对齐 Codex | 到压缩点时如果本窗口没写过自己的笔记，不马上换窗，先给一段超时额度，注入兜底提示：本窗口只允许写一次笔记，然后换窗。 |
| 4 | 主动换窗工具 | 新增类似 Codex `new_context` 的工具，模型记完笔记后自己换窗。第一次提醒时就说明，后续提醒不再重复。 |
| 5 | hint 与模板合并 | 对齐 Codex：常驻说明 + 每窗口一段换窗信息。换窗后不再单独注入 hint。 |
| 6 | 换窗信息只给指针 | 不放笔记全文。顺序：任务、自己的笔记、共享笔记、团队信件，最后是上一窗口 id 和 history 指针。 |
| 7 | 笔记新鲜度 | 自己的笔记文件 mtime ≥ 本窗口开始时间，即视为本窗口写过。workspace.md 不算，不加 token 增量阈值。 |

## 2. 预算提醒（可配置）

配置项沿用 0.2.0：`remindAtRatio`（第一次提醒，默认 0.37）、`compactAtRatio`（上限，默认 0.45）、`bucketStep`（步长，默认 0.03）。

提醒档位 = `remindAt + k × step`，取严格小于 `compactAt` 的值。

新规则：**`(compactAt − remindAt) / step` 不是整数时，去掉最后一次提醒**，因为它离上限不足一个步长。

| 配置 | 档位 | 说明 |
|---|---|---|
| 0.37 / 0.45 / 0.03（默认） | 37、40（43 去掉） | 8/3 不是整数 |
| 0.37 / 0.45 / 0.04 | 37、41 | 8/4 = 2 |
| 0.36 / 0.45 / 0.03 | 36、39、42 | 9/3 = 3 |

按新规则，默认配置只剩两次提醒（37、40），默认步长保持 0.03。

提醒文本：

- 第一次：用了多少、多少时换窗、现在记笔记，**并说明记完可调用换窗工具自己收尾**。
- 之后各档：只说用量和「尽快记笔记、换窗」，不再重复换窗工具的说明。

## 3. 压缩点流程

```
已用 ≥ compactAt
  ├─ 本窗口写过自己的笔记 → 换窗，摘要位置写入换窗信息
  └─ 没写过 → 注入兜底提示，给额外额度 fallbackBufferTokens（默认对齐 Codex 16384）
        ├─ 写了笔记（或调用了换窗工具）→ 换窗
        └─ 用完额度仍没写 → 照样换窗，换窗信息里注明「上一窗口未写笔记，请先用 history_* 恢复」
```

兜底提示（对齐 Codex `auto_compact_fallback_prompt`）：本窗口上下文已用尽，不要继续任务、不要给最终答复；新窗口不会自动带上本窗口内容；现在只调用一次 team_notes 写下检查点（目标、决定、进展、经验、下一步，以及仍在处理的请求在哪个窗口、用什么关键词能搜到），然后调用换窗工具。

待 PoC：

- 插件能否把压缩推迟一轮（45% 是我们自己在 `system-prompt/assemble` 里触发的）；
- 兜底期间能否只暴露 team_notes 和换窗工具：agent-teams 自己用 `agent.ctx.tools.restrict({ deny })` 限制成员工具（capabilities.ts），可以照用；
- 换窗工具能否在工具调用内触发压缩。

## 4. 常驻说明（system section，每个 agent 冻结一次）

分工原则（对齐 Codex：`guidance_message` 只讲规则，`<context_window>` 只给 id）：**常驻说明只放规则，不放路径和状态；换窗信息只放状态和指针，不讲规则。** 同一件事只出现一次。

agent-teams 自身只注入角色说明（`agent-teams:usage`，order 117；成员是 `TEAM_MEMBER_PROMPT`，不含团队名、身份名、任务）。任务契约和 attempt_id 在派发消息里，换窗后就不在上下文中了。所以换窗信息里的身份、任务和 attempt 不与 agent-teams 重复，我们不动 agent-teams。

常驻说明全文：

```
## 团队笔记与换窗
上下文接近预算时会换到新窗口，早先的原始消息不再在上下文中；新窗口开头的【交接】列出你的身份、任务、笔记位置和回看工具。
边做边用 team_notes 记进自己的笔记：进度、结论、决定、下一步；任务约束与用户要求；关键数据与引用（确切路径、命令、报错、数字）；仍在处理的请求在哪个窗口、用什么关键词能搜到。写明哪些已验证、哪些是推测。保持精简，不要抄任务契约。
换窗后先读自己的笔记，缺的细节再用 history_* 回看。
笔记和历史是内部工作记录，不要在对外回复里提起。
（成员）workspace.md 由队长汇总；你主要写自己的笔记，可读本团队所有笔记。
（队长）你负责维护 workspace.md：汇总各成员笔记中对全队有用的结论。
```

与 0.2.0 相比去掉了笔记文件路径（改由换窗信息给出），换窗信息里也不再写「队长维护」「先读它」这类规则。

## 5. 换窗信息

数据来源：

- 窗口 id 用 history 模型的编号（`w1` 起，每个 `compaction/summary` 加一），与 `history_*` 一致，不用 window counter；
- 任务来自 team.json 缓存；
- 笔记元数据来自文件 stat。

首个窗口（还没换过窗）注入精简版：身份、任务和工具指针，没有「上一窗口」一行。换过窗以后注入完整版，取代摘要，不再另注入 hint。

完整版顺序见 §6 样例。超过 `hintMaxBytes` 时，先删除「最近改动的笔记」列表，再删除其余可选行，最后才整条不注入。

## 6. 换窗信息样例（成员 bob）

```
【交接】
团队「接口重构」（team-7f3a），你的身份：bob（成员）。
任务：t2 接口联调（in_progress），当前 attempt 59752a8f
你的笔记：teams/team-7f3a/bob.md（42 行，上一窗口 14:20 更新）
共享笔记：workspace.md（18 行）
最近改动的笔记：teams/team-7f3a/alice.md（30 行，14:05）
队长和队友的信：team_history（含已读）
上一窗口：w2，原文用 history_list_items / history_search_contents / history_read_item 按窗口 id 回看
以上是换窗时的快照，任务和笔记以 agent_teams 工具和 team_notes 为准。
```

未写笔记时，第 3 行改为：

```
你的笔记：teams/team-7f3a/bob.md（42 行，上一窗口未更新，进展需用 history_* 恢复）
```

队长版：任务行改为「团队未完成任务：3 个（t2、t4、t5）」。

## 7. 补充决策（2026-10-16 晚）

1. **换窗工具名**：`context_new_window`，无参数，描述一句：开新窗口，不影响任务和文件状态。
2. **调用时机**：随时可调。本窗口没写过自己的笔记时拒绝，返回「先用 team_notes 记笔记再调；笔记满了就用 write 整篇精简重写」。**每个窗口只拒绝一次**，第二次一律放行，换窗信息标「未更新笔记」（防止笔记写满 `maxFileBytes` 时陷入死循环；以后可能加 LLM 兜底）。
3. **兜底额度**：新增配置 `fallbackBufferTokens`，默认 `16384`（同 Codex）。「写过」只认 `team_notes` 对自己笔记的 write/append。
4. **队长**：不限工具、不强制换窗、不走兜底额度。只在 `compactAtRatio`（45%）和再往后一个步长（48%）各提醒一次，共两次。提醒词单独写，只提示可以记笔记并换窗，不催促、不打压。队长不换窗时由宿主 compaction-basic 约 80% 压缩兜底，仍走插件接管的 `summarize()` 模板，不发 LLM 请求。
5. **w1**：第一个窗口注入精简版交接（身份 + 自己笔记 / 共享笔记 / team_history 指针），不写任务（派发消息里已有）。只在 w1 算一次，不影响前缀缓存。换窗后的完整【交接】放在摘要位置。
6. **配置**：保留 `hintMaxBytes`（默认 4000，也是最低值）、`hintRecentNotes`（默认 5）。超限时不整条丢弃：先减「最近改动的笔记」条数，再截断过长的团队名/任务标题；身份、任务、自己的笔记、上一窗口永远保留。
   - 依据：Codex `ext/history-notes/src/extension.rs:31` `MAX_THREAD_HINT_BYTES = 4_000`，注释「Bound model context even when note paths are unusually long」，超限整条丢并上报 Failed——那是可有可无的服务端 hint 的保险丝；「up to 5」只见于测试夹具，数量由服务端决定，客户端无此配置。我们的交接不可丢，所以改为裁剪。

## 8. 与 agent-teams 的交叉（0.1.23 源码排查）

- agent-teams 无任何压缩相关代码（无 compact / summarize / tokenMeter / contextPressure），不接管 `summarize()`，不改宿主阈值。
- **tools.restrict**：成员启动即 deny 队长专用工具（`capabilities.ts:93`），派发可带 `tool_policy` 白名单（`members.ts:898-903`），`restrict()` 遇未知名直接报错（`harness-compat.ts:301`）。兜底的 restrict 与之叠加，须实测叠加语义、撤销后它的 deny 仍在、agent_teams 工具恢复可见。tool_policy 不含 `team_notes` 时由「只拒绝一次」兜住。
- **agent/pre-step**：成员资格检查可 reject（`members.ts:644`），信箱只把放行进本步的信标已读（`mailbox.ts:64`），命令处理（`command.ts:125`）。插件主路径在组装上下文时压缩，早于 pre-step，本步来信在压缩后进入；换窗工具与宿主 80% 两条新路径需实测来信不丢。
- 角色说明 order 117 只讲协作，与常驻说明不重叠。

## 9a. PoC 之后的修订（2026-10-16 23:05，用户已同意）

PoC 结果见 `docs/research/0.3.0-poc-results.md`。

1. **兜底不再限制工具**（推翻 §7、§8 中的 restrict 方案）。对齐 Codex：`core/src/session/token_budget.rs:161-221` 只注入一次 `AutoCompactFallbackPrompt`（`auto_compact_window.rs:91`），额度加在上限上（`context_window.rs:97-103`），整条路径没有工具限制。PoC 暴露的三个问题（施加/撤销晚一步、成员 Agent 每轮重建后限制丢失、tool_policy 成员看不到 team_notes/换窗工具而卡死）随之消失，也不再因工具集合变化而让前缀缓存失效。
2. **兜底流程**：成员到 `compactAtRatio` 且本窗口未写自己的笔记 → 注入一次强提示（「把进展一次性写进笔记（尽量一次 team_notes），写完立即调用 context_new_window」）+ `fallbackBufferTokens` 额度。成员可见工具里本来就没有 `team_notes` 时跳过兜底，直接换窗。
3. **换窗触发点只有两个**：模型调用 `context_new_window`（视为「笔记写完」的声明），或额度用完。写笔记本身不触发换窗（PoC 里写一次即换，会切断分多次写的笔记）。单次写入是原子的：压缩只在步与步之间发生，`team_notes` 先写临时文件再 rename（`src/notes/store.ts:140-141`）。
4. **交接里「你的笔记」三种状态**：写了且调了换窗工具 →「上一窗口 HH:MM 更新」；写了但被额度强制换窗 →「上一窗口 HH:MM 更新，可能未写完，缺的用 history_* 补」；没写 →「上一窗口未更新，进展需用 history_* 恢复」。
5. **状态按会话 id 存**：兜底中、待换窗标记、本窗口已拒绝过、本窗口写入事件，都不挂在 Agent 实例上（成员 Agent 每轮重建）。兜底状态进入后一直持有，不每步按比例重判（用量会回落，5.04% → 4.66%）。
6. **交接必须带当前 attempt_id**（PoC 中成员换窗后丢失 attempt_id，只能重新认领）。
7. **新鲜度双重判断**：笔记 mtime ≥ 窗口开始（窗口开始 = 最后一次压缩摘要时间），或本窗口记录到 `team_notes` 对自己笔记的写入事件。
8. **接管 summarize()**：每次 `serviceFor` 拿到的是新代理，接管标记打在引擎实例上，不用 WeakSet。宿主自动压缩也走接管后的方法（已实测）。
9. **兜底中模型结束本轮**：等它下次被唤醒的第一步换窗，不主动唤醒，避免与 agent-teams 的唤醒逻辑冲突。
10. 实现后用 5% 测试阈值跑一遍真实团队，重点复测换窗工具路径下同一步来信。
