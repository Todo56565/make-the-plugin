## 2. 普通模式

### 2.1 定义

- **普通会话**：顶层会话（不是子会话），且不是任何团队的队长或成员。
- 子会话规则不变（E1）：非成员、父会话不是队长的子会话照旧隐藏本插件工具。普通会话开出来的子会话也隐藏。
- 不加新设置：现有开关（团队笔记、历史工具、context_remaining 等）同样作用于普通会话。

### 2.2 普通会话能用什么

| 功能 | 普通会话 |
|---|---|
| 窗口计数、提醒、兜底、换窗、交接 | 有 |
| `context_new_window`、`context_remaining` | 有 |
| `history_*` | 有 |
| 自己的笔记（`self`） | 有（新增，见 §3） |
| `workspace.md` 读写 | 有（用户 10-21 同意，与队长一样） |
| `team_history`、队员笔记、待合并清单、全文记录、结束代清理 | 没有（只属于团队） |

### 2.3 状态根

普通会话与团队共用同一个状态根 `<cwd>/<stateDir>/.context/`（默认 `.agent-teams/.context/`）。目录名带 agent-teams 只是历史名字；不另开目录，`workspace.md` 天然是同一份。

## 3. 互接：笔记跟会话走

### 3.1 规则

- 普通会话的笔记按会话存：物理 `notes/sessions/<会话 id>.md`，模型看到的仍是 `self`。
- agent-teams 的队长就是开队的那个会话（`captainSessionId`），所以**队长的笔记就是这份会话笔记**，不复制：
  - 开队前写的内容，开队后队长和队员都能读到（队员读 `captain.md` / `teams/<teamId>/captain.md` 时映射到队长会话的笔记）。
  - 散队后（团队目录移入 archive，身份解析不再命中），会话回到普通模式，笔记原地还在，队长期间写的也都在。
  - 同一会话先后带多代团队，用的都是这一份。
- 队员笔记不变：仍归团队那一代（`teams/nanmi/<teamId>@<代>/<成员>.md`），照旧快照、进待合并、结束代清理。队员的成果经合并进 `workspace.md` 带回给普通会话。
- 插件旧版本的队长笔记（`teams/nanmi/<teamId>@<代>/captain.md`）**不做适配性迁移**、不读（用户 10-21 定），新版从零开始。
- 自己的笔记与 `workspace.md` 分工（10-21 讨论）：自己的笔记 = 这条会话线的工作记忆（正在做什么、进度、下一步），给自己换窗后接上；`workspace.md` = 项目长期共享的知识（约定、决定、架构、坑），任何会话 / 团队都读。提示词里写清这条分工。

### 3.2 换窗与交接

- 普通会话的交接只列：自己的笔记、`workspace.md`、最近改动笔记（只在这两份里取）。
- 队长交接照旧（含待合并、队员笔记），只是自己的笔记路径换成会话笔记。
- 身份在普通 ↔ 队长之间切换时不另发提示；下一次交接 / 常驻说明自然按新身份生成。常驻说明冻结值按身份算，身份变了即重算（E5b 已说明它只取决于角色与开关）。

### 3.3 实现要点

- `src/team/identity.ts`：解析结果从「团队身份或 undefined」改为三态：`plain`（顶层、非团队）/ `captain` / `member`；子会话非成员仍为 undefined。
- `src/notes/paths.ts`：`self` 对 plain / captain 映射到 `sessions/<会话 id>.md`；队员看 `captain.md` 映射到 `sessions/<captainSessionId>.md`。会话 id 做文件名安全处理（沿用 `sanitizeKey`）。
- `index.ts` 里现有 `identity === undefined → 不生效` 的分支（交接、预算、常驻说明、`context_new_window`、`isTeamAgent`）改为只排除 undefined，plain 走普通分支。
- `snapshotOnWindowSwitch` 本来只对 member 生效，不动。
