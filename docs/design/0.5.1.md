# 0.5.1 设计（补丁）

> 状态：进行中，未打 tag。

## F1 headless profile 下可启动

- 问题：`inject` 含 `agentPresets`，headless profile 没有该服务，整插件停在
  `pending (waiting for service: agentPresets)`（E5b PoC 发现）。
- 改法：`agentPresets` 移出 `inject`，在 `compactionEngineOf()` 调用时 `ctx.get('agentPresets')` 读取（同 `llm` 做法）；
  没有时退回 `agent.ctx.get('compaction')`。PoC 已验证 headless 下该路径能取到压缩引擎（`compactIfNeeded` 为函数）。
- 单测：`test/budget/compact.test.ts` 覆盖有 agentPresets / 无 agentPresets / 抛错三种。
- 已验证（10-19）：DSH 0.2.1-rc.2 headless + 本地 mock 启动，插件正常加载（请求里有 context_remaining、context_new_window、history_*、team_notes、team_history 等本插件工具），一轮正常结束。

## F2 鲁棒性修复（桌面端审查报告核查后，10-20）

- 锁接管：锁文件内容读不出（持有者在 `open(wx)` 后、写完前崩溃）时按文件 mtime 判过期，超过 staleMs 即接管；新建未写完的仍等待（`src/context/lock.ts`）。
- 笔记写入改用 `atomicWrite`：Windows 下 EPERM/EACCES/EBUSY 重试，失败不留临时文件（`src/notes/store.ts`）。
- 结束代收尾逐代隔离：某代出错记入 `SweepResult.failed` 并告警，继续收尾其他代，下次照常重试（`src/records/ended.ts`）。
- 信件可见性：agent-teams 移除成员、同 id 换代都不清信箱；`team_history` 只给本代 `createdAt` 之后的信，成员再限于自己 `joinedAt` 之后，同名新成员读不到旧信（`src/team-history/mailbox.ts`）。
- 报告中其余条目核查为设计如此或误报，不改。
